# 30. Glossary

This glossary gives each core term a one-line meaning and points to the chapter with more detail.

| Term | Plain meaning | Chapter |
| --- | --- | --- |
| ABAC | Access based on attributes of the user or data | 10 |
| ACID | Rules ensuring writes are all-or-nothing and reliable | 6 |
| Backfill | Running a pipeline for a past period | 11, 23 |
| Backpressure | Data arriving faster than it can be processed | 20 |
| Bronze, Silver, Gold | Medallion layers holding raw, clean and business-ready data | 6 |
| CAP theorem | During a network split, a system must favor consistency or availability | 12 |
| Cardinality | The number of distinct values in a column | 16 |
| CDC | Copying only the changes made in a source database | 5, 17 |
| Checkpoint | A saved progress marker used for restarts | 17 |
| CI/CD | Automated testing and release of changes | 14 |
| Clustering | Storing similar values close together on disk | 16 |
| Columnar storage | Storing data by column for faster analytics | 6 |
| Compaction | Merging small files into larger ones | 16 |
| Consumer group | Consumers sharing the work of reading a topic | 20 |
| DAG | A set of tasks with one-way dependencies and no loops | 8 |
| Data contract | An agreement on a dataset's schema, meaning and quality | 14 |
| Data lake | Cheap storage holding files of any type | 6 |
| Data mesh | Domain teams own and publish their data as products | 14 |
| Data skew | Some keys holding far more data than others | 19 |
| Data warehouse | A managed database built for analytics | 6 |
| Dead-letter queue | A holding place for messages that could not be processed | 22 |
| Dimension table | A table describing the context of events | 15 |
| ELT and ETL | Transforming data after or before loading it | 5 |
| Event time | When something actually happened | 20 |
| Exponential backoff | Waiting longer after each failed retry | 22 |
| Fact table | A table of measurable events | 15 |
| Grain | What one row in a table represents | 15 |
| High-watermark | The latest value already loaded | 17 |
| IaC | Defining infrastructure in version-controlled code | 14 |
| Idempotent | Running it again gives the same result | 18 |
| Lakehouse | A data lake with warehouse-style table features | 6 |
| Lineage | A map of where data comes from and goes | 10 |
| Materialized view | A stored query result that is refreshed | 24 |
| `MERGE` (upsert) | Updates matching rows and inserts new ones | 18 |
| OLTP and OLAP | Systems that run the business, and systems that analyze it | 6 |
| Offset | An event's position in a partition | 20 |
| Partition pruning | Skipping partitions that cannot match a filter | 24 |
| Partitioning | Splitting data into pieces by a column or key | 12, 16 |
| PII | Data that can identify a person | 10 |
| Predicate pushdown | Applying filters during the scan | 24 |
| Quarantine table | A table holding rows that failed checks | 21 |
| RBAC | Access based on a person's role | 10 |
| Reconciliation | Comparing totals between systems | 21 |
| Reverse ETL | Copying warehouse data back into business tools | 9 |
| RPO and RTO | How much data you can lose, and how long you can be down | 11 |
| Salting | Adding a random value to spread out busy keys | 19 |
| SCD | Rules for handling changes to dimension data | 15 |
| Schema evolution | Handling changes to a table's structure over time | 17 |
| Semantic layer | One shared definition of metrics and relationships | 9, 25 |
| Shuffle | Moving rows between machines to group matching keys | 19 |
| SLA, SLO and SLI | The promise, the internal target and the measurement | 13 |
| Star schema | A fact table joined directly to its dimensions | 15 |
| Surrogate key | An ID generated by the data system | 15 |
| Tokenization | Swapping a sensitive value for a token | 26 |
| Watermark (streaming) | How long a stream waits for late events | 20 |
| Window function | A calculation across related rows that keeps every row | 18 |
| Write-Audit-Publish | Writing to staging, checking, then releasing the data | 21 |
